# 嵌入式 Linux 调试

遵守仓库 AGENTS.md。从仓库根的 `docs/project1-环境与验证.md` 获取环境线索，按故障读取架构文档和真实源码；文档里的环境缺项可能已经变化，需核实。

1. 明确现象、预期、触发输入、复现命令、最近改动及所用 demo。区分 x86_64 开发机、交叉编译环境和 RK3588 板端；已有信息不重复询问。
2. 收集现有日志、错误返回和调用链。输出日志前去掉凭据和认证流地址。编译错误先核对实际 CMake 入口、编译器目标、头文件与库路径，不通过盲目安装或升级消除错误。
3. 区分代码事实、推测和待验证问题。提出少量有证据支持的假设，为最可能原因设计最小实验，每次尽量只改变一个因素。
4. 卡住或退出异常时追踪停止标志到阻塞读、重连循环、条件变量、join 及资源释放；图像异常时核对格式、stride、共享像素和底层缓冲有效期。
5. 在当前授权内执行实验及最小修复。只要求诊断时保持只读；运行涉及设备或外部推流时先核对对应授权。没有板端访问条件时继续可行的静态定位，并标明未验证部分。
6. 修复后在同类条件复测，并覆盖与改动直接相关的正常或错误路径。证据不支持原假设时调整假设，不连续堆叠试探性修改。

交付现象、关键证据、原因或仍存假设、修改/建议以及验证结果。分别标记静态检查、编译、主机测试和板端运行；未执行写明未执行。没有复现不代表问题不存在，编译通过不代表运行问题解决。
