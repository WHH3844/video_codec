# 嵌入式 Linux 审查

遵守仓库 AGENTS.md。以仓库根的 `docs/嵌入式软件架构.md` 和 `docs/project1-环境与验证.md` 为定位线索，所有结论回到当前源码验证。

- 先确定差异审查还是已有模块审查。对差异读取 diff 与必要上下文；对模块读取真实构建入口和必要调用方。没有 Git 差异不等于模块无缺陷。
- 默认只读，不自动修改、格式化或运行视频程序。用户同时要求修复时，在授权范围内完成后再核对结果。
- 重点检查共享像素并发读写、裸指针和 DMA/MPP 缓冲生命周期、停止标志是否能结束阻塞与重连、join 与 delete 次序、初始化部分失败后的清理、错误返回及参数边界。
- 平台问题核对目标架构、库 ABI、路径和实际采用的代码分支；不能只因存在 RKNN/RGA 接口就判定硬件路径工作正常。
- 每个问题给出优先级、文件行号、触发条件、具体后果、代码证据及最小修复建议。把有代码证据的缺陷与需运行验证的风险分别说明；差异审查区分新增问题和已有问题。
- 不把个人命名或格式偏好当作缺陷，不为凑数量制造问题。未发现有依据的问题时直接说明，并列出范围及验证限制。

示例请求：`$embedded-linux-review 只审查多模型 demo 的退出流程，沿线程和 loader 的生命周期找证据，不修改代码。`
